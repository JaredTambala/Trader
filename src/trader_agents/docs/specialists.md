# Current Specialist Agents

## Data Research Agent

The Data specialist works against a typed composite scope that may contain multiple assets, pairs, timeframes, date
ranges, sources, and dataset roles. The model selects among discovery, inventory, quality, bounded loading, operation
reconciliation, snapshot, and canonical-read tools. Code validates every call against the delegated scope.

It returns readiness per scope item, canonical dataset/quality/loading references, limitations, blockers, and a
recommended next step. It cannot change the research question, choose strategy semantics, accept partial scope as
complete, or call a provider outside configured capability and cost policy.

## Strategy Engineering Agent

The Strategy specialist receives a typed build contract and required input references, but no protected outcome data.
It must search and compare the implementation catalogue before choosing exact reuse, adaptation, or new authoring.
When code work is required, it uses only the isolated Coding Workspace tools, packages the candidate, and sends the
exact source through normal validation and immutable registration.

It can repair an admission failure within its reserved revision budget. It cannot weaken the contract, infer missing
behavioral semantics, use backtest outcomes to tune code, run host commands, admit its own source without validation, or
leave a workspace behind.

## Adding another specialist

A new specialist requires a complete role record: mission, exclusive decisions, entry/context/trust boundary, model
program, tool allowlist, phases/invariants, public state, evidence return, termination, evaluation, concurrency, and
coordinator handoff. It also requires an owning MCP capability set and behavioral tests. Adding a responsibility name to
an enum is not sufficient to create an agent.
